El problema

Los datos existen. Las decisiones llegan tarde.

~500 pacientes / día

Urgencias, hospitalización y consulta generan mucha información cada jornada.

Información dispersa

Historia clínica, farmacia y admisiones viven en sistemas distintos y en Excel.

Reportes manuales

Directivos piden tablas a TI o las arman a mano. Pierden horas críticas.

Impacto: calidad de atención al paciente y eficiencia del gasto en salud.

Objetivos del prototipo

Lo que pedía el reto — y lo que entregamos

1. Consultar en español

El agente, paso a paso

Planner → Node → Predictor → Recommender

1. Planner

Traduce la pregunta a un pedido seguro de datos (DSL).

2. Node

Revisa el pedido y trae filas del HIS. Aquí se protege la base.

3. Predictor

Si hay historia suficiente (≥12 días): Random Forest. Si no: tendencia simple.

4. Recommender

Sugiere una acción operativa (ej. revisar stock o capacidad).

El agente nunca ejecuta SQL directo ni abre la base de datos.

Seguridad y confianza

En un hospital, la IA no manda sobre los datos

El agente no toca la base

Solo propone un pedido. Node lo revisa y ejecuta.

Roles distintos

Farmacia, director y admin no ven lo mismo.

Sin datos personales en el chat

Respuestas agregadas: totales y promedios, no nombres.

Claves y auditoría

Secretos fuera del código; lecturas sensibles quedan registradas.
